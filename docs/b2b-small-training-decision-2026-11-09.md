# B2B手本2本を使う小規模学習：進め方の決定案

2026年11月9日。`docs/b2b-demo-2026-11-09.md` と現行の `scripts/opening_rehearsal.py` を読んだ上での、Claude向けの具体的な実験仕様。この文書を作る際には、学習・実エンジン評価・本番変更を行っていない。

## 今回選ぶ条件

| 項目 | 条件 |
| --- | --- |
| 開始モデル | 採用済みd16384の固定base＋chain-head。停止中の5回目の候補は使わない |
| 学習 | 隔離した新rootで4,096環境判断、未使用の学習seedを1つ事前登録、候補1つ |
| 基本条件 | 学習率1.5e-5、PPOの設定は従来どおり、復習λ=5、KL=0、復習2系列/ミニバッチ |
| B2Bデモ | 正常終了し再現も照合済みの手本A・Bの2本だけ。異常終了した実行2は除外 |
| デモの追加生成 | 今回はg01・g02等を増やさない。元の6回上限の残り1回も使わない |
| サンプリング | 復習系列の87.5%を旧416本、12.5%をB2Bデモ。B2B枠内はA・B各50% |
| 固定方法 | 8ミニバッチ＝16系列ごとに、旧14本・A1本・B1本。枠の位置を固定seedでシャッフルし、旧枠は旧416本から一様抽出。順番と実際の抽出回数を記録 |
| 発動判断のラベル | 付ける。手本で有効な継続を確認した局面に限り、B2B③の発動も教師対象とする |
| 評価用初手 | 提案のg03・g05とseedを学習前に固定。成立しない場合は、学習・結果閲覧の前にその旨を記録し計画を改める。結果を見て都合のよい初手へ差し替えない |
| 評価の実行回数 | B2B比較12回＋候補の既存66件保持試験66回＝最大78評価エピソード。PPO自己対戦は別枠で4,096環境判断が上限 |
| 本番 | STOP・pending・5回目の候補・採用モデル・既存データ・既存記録は不変。通常運転・対戦評価・採用は行わない |

これはD条件を土台にB2Bデモを混ぜる新しい試行であり、以前のD条件とデータ分布が同一という扱いにはしない。混ぜる割合は初回試行用の固定値で、効果や安全性が実証済みの最適値ではない。

## 1. 発動にもラベルを付ける理由と範囲

今回の目的には、役立つ局面で自分からB2B③を使えるようにすることを含める。そのため、手本A・Bの検証済みの発動時点にも損失をかける。ルールで発動を強制する実装はしない。

発動判断を教師対象から外しても、共有する重みへの他の更新やPPOによって発動確率は変わる。「発動ラベルなし＝発動判断に中立」という保証はない。

ただし、次の制限を守る。

- デモの各局面に対応するラベルに限定する。B2Bを発動できる全局面を一律に正例にはしない。
- パスした時点は今回の教師損失から除外する。これはパスが悪手だと定義することではない。
- 同じ局面で合法性と有効な継続を確認できた選択肢だけを許容集合に入れる。対象のキューとザレンを同じ選択画面で許す場合も、対応する状態を照合する。
- トラックメイカーのサーチ先を、未検証のプレイリスト等にまで広げない。まず実証済みのシンクロを使う。
- 分岐後の別々の局面のラベルを、カード名やレベルが似ているという理由だけで合併しない。
- レベル3チューナー枠はうらら必須という仕様にしない。ただし今回実行したデモはうらら版で、レコ版の全経路を検証済みとは書かない。

## 2. 文脈と損失マスクの実装条件

現行 `opening_rehearsal.prepare()` は、`weights > 0` が系列の全実段階に対応することを検査し、実段階から配置・表示形式だけを除いて損失マスクを作る。したがって、ターン1等の文脈の `weights` を0にする方式では、この計画を実装できない。

- 実際の系列長・paddingの有効性と、教師損失の対象かどうかを別に表す。独立したデモ用の損失マスク等を追加する。
- 自分のターン1と、ターン2・3の損失対象外の判断も、実際に実行した履歴としてRNNに順に通す。
- 配置・表示形式・paddingは従来どおり損失対象外。未ラベルの文脈をpaddingとして削らない。
- prefixに直接の教師損失が無くても、共有重みやRNNを通じた勾配により先攻展開は変わりうる。これを保持保証とは扱わず、既存66件で測る。
- 旧データ・旧経路は、追加機能を無効にした場合に従来と同じ動作になることを確認する。

B2Bデモは旧gateでは不合格になる経路である。旧416本のファイルや合否記録を書き換えず、独立したデモ用データ・manifest・ハッシュ・検証状態として管理する。旧gate合格を意味するフラグを付けて読み込みを通す回避はしない。

12.5%は系列の抽出割合であり、損失や勾配の12.5%を意味しない。旧データとB2Bデモで損失対象判断数が違うため、実際の系列数・対象判断数・CE・重み付け後の勾配ノルムを分けて記録する。今回、観測した数値を見て比率やλを途中変更しない。

## 3. 評価と回数の数え方

B2B側の12回は提案どおり。

1. g03・g05でB2Bへ着地する手順の記録と再現：2初手×2回＝4回。
2. 同じ2初手で学習前・学習後を比較し、それぞれ記録と再現：2初手×2モデル×2回＝8回。

これとは別に、最終候補を既存66件で1回評価する。採用モデルの保持基準は、重み・ケース・評価コード・補助の版が一致する既存結果を照合して使う。基準の再評価が必要と判明した場合は、78回の上限を黙って超えず、追加実行前に計画を再登録する。

g03・g05はtrain区分であり、旧416本の復習などで既知である可能性がある。「完全に未学習の初手」「未使用holdout」とは呼ばない。今回新しく追加するB2B手本には使わない初手への、B2B使用法の転移確認として報告する。

評価局面を先に固定し、学習前の結果も保存する。その後に候補を1つ作り、最終4,096判断だけを比較する。途中チェックポイントを見て候補を選び直さない。4,096判断・1学習seedの試行なので、改善があっても学習seed間の再現性や対戦の強さまで証明したとは書かない。

### 報告するもの

- B2B③：使える機会、発動、対象、回収/特殊召喚、追加S召喚、実際に残った資源。
- 攻撃：合法な攻撃の機会、選択、2回目の攻撃、LP、デュエル終了。発動率や攻撃率だけを成功指標にしない。
- 自分のターン終了・相手ターン終了・次の自分ターン終了の3時点の状態。
- 既存66件の成功集合と、増えた/失ったケース。成功数だけで保持を判定しない。
- 旧手本とB2Bデモ別の抽出回数・損失対象判断数・損失・勾配、資源使用量、データ/コード/開始モデル/最終モデルのハッシュ。
- B2B③の使用でサーチ自体が無効になったと誤記しない。

観測入力が一致した操作列の再現と、別の学習seedで同じ改善が出ることは別である。今回は前者だけを再現回数に含める。

## 4. 続行と終了

実装とマスク・サンプリングの検証を終え、計画・データ・コード・seedを固定してから、指定の1区間を学習する。候補は本番に採用しない。既存保持が落ちた場合も、その事実を報告し、条件を後から緩めない。

結果が変わらない場合も、有効性が分からなかった初回試行として残す。その場で追加学習・手本増量・比率変更を重ねない。
