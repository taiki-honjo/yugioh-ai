# 青眼デッキ：ローカル学習の初回試行

記録日：2026年10月27日（日本時間）。このPCで実行して確認した結果です。

## 確認できたこと

- Ubuntu 22.04をWSL2で起動し、RTX 4060 Tiを認識。
- JAXでGPUの行列計算に成功。
- 同梱の青眼デッキで、ランダム行動による4戦を完走。
- 4並列・32更新・4,096判断分のGPU学習を実行し、モデル保存を確認。
- 保存したモデルを別プロセスで読み込み、4戦を完走（ランダム相手に2勝2敗、seed=100）。
- 保存した重みを読み込み、さらに512判断分・4更新を実行して再保存。
- 追加学習前後で重みが変化し、保存した最終パラメータがすべて有限値であることを確認。

対戦数・学習量とも小さいため、強さが向上したかは未評価です。2勝2敗を安定した勝率と解釈しないでください。

短い追加学習のログには、まだ対戦が終わっておらず平均を計算できない時点の `avg_return=nan` が含まれます。これは集計用の値です。保存した最終モデルの全パラメータが有限値であることは別に検証しています。

Ubuntuユーザー：hatk8。Python仮想環境：`/opt/ygo-ai/.venv`。実行ソース：`/opt/ygo-ai/current`。

主なバージョン：Python 3.10.12、JAX/JAXLIB 0.4.28、Flax 0.8.4、Optax 0.2.2、NumPy 1.26.4。PyTorchは共通ユーティリティのためCPU版2.3.1を使用。学習はJAXのGPU実行です。全依存関係はrequirements-resolved.txtに記録しました。

## 実測結果

| 項目 | 結果 |
| --- | --- |
| 保存修正後の4,096判断分の学習 | 52.0秒 |
| 同実行のGPU全体メモリ使用量の最大 | 2907 MiB |
| 同実行の子プロセス最大RSS | 1900 MiB |
| 512判断分の追加学習 | 42.3秒 |
| モデルのパラメータ数 | 4,343,242 |
| 追加学習で値が変わったパラメータ数 | 3,248,221 |

時間はPython起動・初期化・コンパイル・内部評価を含みます。初回の学習実行は約98秒、GPU全体メモリ最大5210 MiBでした。その初回では後述の保存不具合が発生したため、修正後に再実行しています。再実行時はコンパイルキャッシュを利用できる状態であり、初回との単純な速度比較はできません。GPU値にはWindowsや他のアプリの使用分も含まれます。最大RSSはLinux子プロセスの値で、PC全体のRAM使用量ではありません。

## 起動と再実行

PowerShellからUbuntuを開きます。

```powershell
wsl -d Ubuntu-22.04
```

UbuntuからWindows側へ戻るには `exit` と入力します。

短い学習を再実行する場合は、Ubuntu内で以下を実行します。これは新しいモデルを初期化する実行です。

```bash
bash /mnt/c/Users/hatk8/Documents/Codex/2026-10-27/new-chat/outputs/ygo-ai-trial/train-blueeyes.sh 4096
```

今回保存した重みから追加学習する場合は、第二引数にモデルのパスを渡します。

```bash
bash /mnt/c/Users/hatk8/Documents/Codex/2026-10-27/new-chat/outputs/ygo-ai-trial/train-blueeyes.sh 4096 /mnt/c/Users/hatk8/Documents/Codex/2026-10-27/new-chat/outputs/ygo-ai-trial/blueeyes-4096-plus512.flax_model
```

新しい実行結果は `/opt/ygo-ai/experiments/manual-日時/` に保存されます。決定回数は128の倍数で指定します。

**追加学習は、学習済みの重みを引き継ぐ方式です。最適化の内部状態・乱数状態・対戦途中の状態を完全に復元する機能は、現状の実装には含まれません。**

## 保存ファイル

- blueeyes-4096.flax_model：4,096判断分の学習後のモデル。
- blueeyes-4096-plus512.flax_model：上記の重みから512判断分を追加学習したモデル。
