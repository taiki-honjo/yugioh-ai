| 変更 | 内容 |
| --- | --- |
| 価値損失 | `min(0.5·(V−目標)², 1.0)` → `0.5·(V−目標)²`。誤差が√2を超えると勾配が0になる問題を除いた。誤差が約50でも、価値の勾配で誤差が縮むことを実モデルで確認。PPOのratio clipはそのまま |
| 復習 | 旧40系列（既存24＋対16）を `hb_data.BlockSampler` で抽出（4バッチ1組＝既存群2＋対2、各2系列、長さ115）。source別の記録を9群に対応させた |
| 終局の分類 | `termination_reason` で判定する。**自然決着**：最後に判断した側から見た報酬の符号で+1/−1/0。**ステップ上限**：0とし、別に数える。**タイムアウト**：その対局のうち、未処理windowにある判断を更新から外し、勝敗は作らない |
| 判断上限での打ち切り | 学習側が次に判断する場合はexact bootstrap。相手側が次の場合は、未完了の対局の判断を更新から外す（今回は学習側が次だったので、捨てた判断は0） |
| その他 | 最後の対局で短いwindowも更新する／実時間の上限で穏当に停止する／進捗をfsyncして保存する／推論時間を記録する |

- seed列（学習256個・評価64個、重複0）。

## 5. 制約・未確認

- **1seed・1候補・81局分の学習。** 小さな勝率差は区間内に収まっている。
- **自然な引き分け**：このネイティブ環境では、勝者なしの決着をAPIで識別できない。最後に判断した側に−1が返る（ygopro.h）。学習でも `scripts/evaluate.py` でも同じ扱いになる。今回の自然決着208局（学習80＋評価128）で、これが起きたかは確認できない。
- **盤面記録の山札枚数**：ネイティブのsnapshotに山札が含まれないため、`eval/battles/games/*.json` の `deck` は常に0。実際の枚数ではないので使わない。手札・墓地・除外・場の公開情報は記録できている。
  - 通常ドローが起きていることは記録から確認できた。128戦中108戦で、後攻の手札がターン1開始時の5枚から、ターン2の最初の判断時に6枚になっていた。残りの20戦は、ターン1に手札を使った対局。
- **情報漏れ**：公開カードの監査は由来（選択画面／由来不明）を記録している。「露出0件」によって、すべての経路の情報漏れを否定するものではない。
- 学習中のメモリ上の重みとファイルの比較は、変更記録1の事情により実施できなかった。代わりに、ファイルを2つの読み込み経路で照合した。
- `rlt_train.py` の後片付けの不具合は修正していない（記録のまま）。同じコードを再利用する場合は、`del env` の後にチェックする必要がある。
