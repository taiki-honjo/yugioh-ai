## 3. 実行回数と不具合（上限6回、使用5回）

| 回 | 内容 | 結果 |
| --- | --- | --- |
| 1 | 手本Aの実行 | 成功 |
| 2 | 手本Bの実行 | **プロセスが異常終了（exit −11、セグメンテーション違反、Pythonのエラー表示なし）** |
| 3 | 手本Bの実行（修正後） | 成功（デュエル終了まで） |
| 4・5 | 手本A・Bの再現確認 | すべて一致 |

**2回目の原因（推定）**
- 致死の攻撃でデュエルが終わった後に、ハーネスが終了済みのデュエルの状態（`benchmark_snapshot()`）を読んだため、と考えられる。
- 手本Aはデュエルが終わらないので、影響を受けなかった。

**修正**
- 終了した段では、その段の戻り値（報酬・`win_reason`）だけを記録し、エンジンの状態は読まない。
- 修正後の3回目と5回目は、同じ段で正常に終了した。

**記録の扱い**
- 2回目は、台帳に開始だけが残っていた。終了の行は事後に「crashed」として追記した。ログは `logs/run-DM-B-crashed-run2.log` に改名して残した。

## 4. 手順2・3の計画案（承認待ち）

### 4.1 手順2：train専用の小規模な追加学習（案）

| 項目 | 案 |
| --- | --- |
| データ | 手本A・Bの2本（どちらもtrainの初手 g00）。必要なら、ほかのtrainの初手（例：g01、g02）で同じ着地と手本を作って追加する（その場合は実行回数が増える） |
| 損失をかける判断 | ターン2・3で、B2B・攻撃に関わる判断だけ（手本Aで11、手本Bで8）。自分のターン1（54段）は文脈だけに使い、損失はかけない。同じ初手に、既存の復習データではP1の流れのラベルがあり、それと衝突させないため。パスの時点にもラベルを付けない（受け身を教えないため）。配置・表示形式の補助が担当する判断も、従来どおり除く |
| 許容する選択肢の集合（規則にしない） | B2B③の対象：{キュー, ザレン}（どちらも可）。トラックメイカー①の検索先：{シンクロ, プレイリスト, …}。攻撃：弱い相手モンスターへの攻撃と直接攻撃 |
| **未決の点①** | B2B③を「発動する」判断にラベルを付けるか。付けると使う方向へ押す。付けなければ中立で、発動した後の選び方だけを教える。強制規則にしないという方針からは、後者が近い |
| **未決の点②** | 手本の混ぜる割合。既存の416系列に2系列を足しただけでは、ほとんど抽出されない |
| 学習 | 新しい隔離rootで、採用モデルから開始する。D条件（学習率1.5e-5、復習λ5）、4,096判断（1区間）。validation・holdoutは使わない |

### 4.2 手順3：事前に固定した別の初手・seedでの比較（案）

| 項目 | 案 |
| --- | --- |
| 評価する局面 | train `jj-cue-reco` 系統のうち、手本に使っていない別の初手の候補：<br>- g03（キュー、調和ノ天救竜、レコ、ドロール、ヴェーラー。seed 151101）<br>- g05（キュー、G、幽鬼うさぎ、レコ、ドロール。seed 151115）<br>学習の前に固定する。それぞれ、自分のターンでB2Bに着地する流れが成立するかを、先に確かめる必要がある |
| 比べる内容 | 学習前と学習後のモデルに、ターン2・3を判断させる（今回と同じく、自分のターン1は記録で再現し、相手はO1）。B2B③の使用と選択、攻撃の選択、資源とLPの変化を3時点で記録する |
| 保持 | 既存の66件（gateと同じ評価）。必要なら固定試験の88件も |
| 実行の上限（案） | 着地の確認：2局面 ×（実行＋再現）＝4。比較：2局面 × 2モデル ×（実行＋再現）＝8。計12回 |
| 対戦・採用 | 行わない。採用条件の見直しは、この比較と対戦の結果を見てから |
