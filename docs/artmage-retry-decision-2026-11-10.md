# Claude向け：Artmage学習の観測検査修正と1回の再試行

2026年11月10日。ユーザーからの停止報告、元の実行ログ、現行の観測生成・公開記録のソースを読んだ上での判断。この文書を作る際には、実エンジン・学習・評価を追加実行していない。

## 決定

**「修正して最初からやり直す」を選ぶ。追加の学習実行は1回だけ、上限4,096環境判断。**

旧検査の「相手の手札・デッキのカードIDは常に0」は、合法な公開でも成立しない。これを学習の停止条件から外し、可視化されたカードを記録して続行する修正は、今回の隔離した試運転の範囲で進めてよい。

ただし、可視化されたカードすべてを「公開済みと確認できた」と認定する変更にはしない。根拠を確認できないものは**公開由来未検証**として残す。情報漏れが無いことを実証済みとは報告せず、監査が不十分な場合は候補と評価を探索的な参考結果として扱い、採用や対戦の強さの認定に使わない。

## 確認できたこと

- `train/attempt-1-failed/episodes.jsonl` では、総判断数は**2,680**。2,316はその前の完了エピソードまでの値。
- `windows.jsonl` は20更新窓。最後の更新窓は総判断数2,617で終了し、20窓ともbootstrapは `exact` と記録されている。
- 失敗時点のエピソードの学習側初手には三戦の才がある。ただし、所持していたことだけでは、停止した時点でその手札確認効果を使った証拠にはならない。
- nativeのSHA256は `19a60f38a3d39b61a2ee082168d5a788a1022b2eb569633816596c8b3de21294` のまま。
- `ygopro.h` の `knows_card()` と `_set_obs_cards()` は、閲覧者・カード所在・コードに対応する公開記録を参照して観測を作る。
- `MSG_CONFIRM_CARDS` は指定した閲覧者への公開、`MSG_CONFIRM_DECKTOP` は両者への公開を記録する。移動・手札/デッキのシャッフル・チェーン終了ではその位置に関する公開記録を消す実装。
- 三戦の才のローカルスクリプトにも、手札確認で `Duel.ConfirmCards(p,g)` を呼ぶ経路がある。

これは、合法な可視化の実装が存在し旧検査が一般には不適切だという確認である。失敗時点の全可視カードについて公開の由来を再現・照合できたという意味ではない。

## 修正と記録

1. 相手の手札・デッキのIDが非ゼロという事実だけで異常としない。
2. ログ上の名称は、確認していない段階で `privacy_violation` や `verified_disclosure` と断定しない。可視化イベント／公開由来未検証を区別する。
3. 最低限、エピソードとseed、環境判断番号、閲覧者・学習側/固定相手側、ターン・局面、メッセージ、可視カードの領域・観測行番号・ID、公開チェーン、直前の実行行動を監査用に残す。
4. 取得可能な公開イベントや選択画面と対応付けられるものは、その根拠も記録する。現在のPython APIで対応付けできないものは未検証のまま残す。
5. 監査用に取得した生の情報を、方策・RNN・PPO/復習の入力へ混ぜない。観測の内容そのものをこの修正で変更しない。
6. 非公開の初期状態、公開の閲覧者、移動等による公開記録の失効について、今回読んだソースに沿う検査・テストを維持する。合成テストと実エンジンでの実証は区別する。
7. 明らかな未公開情報の露出や閲覧者の取り違えが確認できた場合は、単なるログ対象として押し切らず中止する。

評価側も同じ方針にする。行動ID、合法な選択肢の番号、公開チェーンの長さ、重み・コード・デッキのハッシュ照合は引き続き厳密に扱う。

現行runtimeの原本を上書きしたり、観測生成の挙動を変えたりしない。公開由来の独立した診断APIが必要だと分かった場合は、それを追加したことと検証範囲を別途明示し、単なるPython検査修正だったと報告しない。
