## 4. 評価結果の解釈上の注意点

- **先後ペア比較**: 同じ乱数シードで候補モデルが先攻（Player 0）と後攻（Player 1）の両方をプレイしています。「2連勝」は初手運や先攻・後攻の有利不利に関わらず候補モデルが両方勝ったペア数、「1勝1敗」は片方の席でのみ勝ったペア数です（タイムアウトまたはタイムアウト疑いを含むペアは `suspected_or_timeout_pairs` として分離し、確定ペア集計には含めません）。
- **95%信頼区間（ペア単位 Clopper-Pearson 保守区間）**: 独立な観測単位はシードペア $K$ 組（各ペアスコア $P_i \in \{0, 0.5, 1\}$）です。$K=1$ を含む全サンプルサイズで有効サンプルサイズを $K$ 組のまま扱い（2戦の独立試行に水増しせず）、下限に `j_low = floor(sum(P_i))`・上限に `j_high = ceil(sum(P_i))` を用いた正確二項（Clopper-Pearson）区間を表示しています。$\{0, 1\}$ 値分布（および $P_i \equiv 0.5$ の退化分布）で被覆率 $\ge 95\%$ が保証され、3値 $\{0, 0.5, 1\}$ の単体格子全体でも数値的に被覆率 $\ge 95\%$ を確認しています（なお一般の $[0, 1]$ 分布では凸順序 $\le_{cx}$ から直接点ごとの二項尾確率支配は従わず Bentkus 2004 の定数因子が伴うため、本評価の3値ペアスコアに対しては上記 Floor/Ceil Clopper-Pearson と格子検証を根拠としています）。信頼区間が重なっている場合は「統計的に明確な強さの差はまだ断定できない」ことを示します。
- **ステップ上限打ち切り（Truncated）と総合勝率**: 1戦の環境ステップ数が `max_steps`（デフォルト `1000`）に達した場合、C++エンジンはLP比較で勝敗を付与して終了します。表1の「総合勝率 [LP判定込]」および95%信頼区間にはこの打ち切り時のLP判定が含まれます。一方、通常決着（`normal_lp0` 等）とは区別して `truncated=True`（異常終了・打ち切り）に分類し、表1に「自然決着のみ（打ち切り・異常終了除外）」の記述統計と「打ち切り率」を併記しています（※打ち切り除外のみの勝率は長期戦を除いた選択バイアスを含むため、自然決着の勝率を主指標とする場合は `max_steps` を増やした再評価を検討します）。
- **タイムアウト（確定 vs 疑い）と採用ルール**: ネイティブ側からスロット単位のタイムアウト通知（`termination_reason == 2`、`timeout=True`、`step_time >= timeout` 等）または例外が確認された場合は `engine_timeout`（確定タイムアウト）として個別エピソード上は引き分け（報酬0）に補正しますが、この補正スコアは実力を反映しないため、確定タイムアウトを含むシードペアもペアごと確定の勝率・信頼区間・シードペア集計から除外します。ネイティブ側のスロット識別情報が無くバッチ全体の壁時計時間が `timeout` 秒以上に達した場合は、未確認スロットの生 `outcome` を一括で引き分けに書き換えず個別エピソードおよび `raw_including_suspected` に診断用として保持する一方、C++ `handle_timeout()` のダミー終端状態が混入している可能性があるため `abnormal=True`・`reason_label='timeout_suspected'` に分類し、正常決着（`normal_total` / `normal_lp0` / `natural_only`）および確定の勝率・シードペア集計（`wins` / `win_rate` / `win_rate_ci95` / `seed_pairs.verified_pairs` / `seed_pairs.sweep_2_0_wins` 等）から除外した上で `requires_rerun_or_exclusion=True`（要再実行または採用除外）と判定します。
- **判断時間（均等按分推定値 vs 実測コスト）**: 初回XLAコンパイル時間（ウォームアップ）を除外しています。「候補推論 按分推定 (ms/判断)」は固定サイズ（`num_envs`）のバッチ推論時間 `dt` をそのステップの有効手番スロット割合（`n_active / num_envs`）で均等按分した推定値であり、個別スロット単体の実測時間ではありません。「候補推論 実測コスト (ms/判断)」はバッチ推論の実測総時間（`candidate_model_batch_wall_seconds`）を有効判断総数で割った実行全体の有効判断あたりコストです。
